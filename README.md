# Khiyar — Hadi Panel

پنل مدیریت VPN مبتنی بر **[3x-ui](https://github.com/MHSanaei/3x-ui)** (ثنایی) که داخل یک کانتینر Docker، پشت **nginx** اجرا می‌شود و برای دیپلوی روی **Railway** آماده شده است.

این پروژه سه کار اصلی انجام می‌دهد:

1. پنل 3x-ui را روی مسیر مخفی `/managepanel/` در دسترس قرار می‌دهد.
2. لینک اشتراک (Subscription) را هوشمند مدیریت می‌کند: اپ‌های VPN متن خام می‌گیرند و مرورگر یک صفحه‌ی زیبا (کارت + QR + کپی) می‌بیند.
3. ترافیک اینباندها (VLESS / WebSocket و ...) را به پورت داخلی `8080` هدایت می‌کند.

## معماری

```
                     اینترنت
                        │
                 Railway Edge Proxy (HTTPS)
                        │
                        ▼
              nginx  (پورت 3000)
                        │
   ┌────────────────────┼─────────────────────┬──────────────────┐
   │                    │                     │                  │
/managepanel/         /sub/               /rawsub/             /  (بقیه)
   │                    │                     │                  │
   ▼                    ▼                     ▼                  ▼
x-ui پنل           تشخیص User-Agent     x-ui ساب (2096)    اینباند (8080)
(2053)             ├─ اپ VPN → 2096
                   └─ مرورگر → sub-view.html
```

- **nginx** تنها سرویسی است که به بیرون باز است (پورت `3000`).
- **x-ui** (پنل و ساب) فقط داخل کانتینر روی `127.0.0.1` گوش می‌دهد.
- هر مسیری که به هیچ‌کدام از مسیرهای بالا نخورد، به پورت `8080` می‌رود؛ یعنی اینباندی که در پنل می‌سازید باید روی پورت `8080` ساخته شود.

## ساختار فایل‌ها

| فایل | کاربرد |
|---|---|
| `Dockerfile` | ساخت ایمیج: نصب nginx، fail2ban، iptables و دانلود آخرین نسخه‌ی 3x-ui |
| `start.sh` | اسکریپت اجرا: تنظیم پنل با CLI، ساخت کانفیگ nginx، اجرای x-ui و nginx |
| `nginx.conf.template` | قالب کانفیگ nginx (متغیر `${NGINX_PORT}` موقع اجرا جایگزین می‌شود) |
| `sub-view.html` | صفحه‌ی نمایش زیبای لینک اشتراک برای مرورگر |

## پورت‌ها و مسیرها

| پورت | سرویس | دسترسی |
|---|---|---|
| `3000` | nginx | عمومی (پورتی که Railway به آن وصل می‌شود) |
| `2053` | پنل 3x-ui | فقط داخلی |
| `2096` | سرویس ساب 3x-ui | فقط داخلی |
| `8080` | اینباند (VLESS/WS و ...) | فقط داخلی، از طریق nginx |

| مسیر | رفتار |
|---|---|
| `/managepanel/` | پنل مدیریت |
| `/sub/` | اپ VPN → متن خام ساب؛ مرورگر → `sub-view.html` |
| `/rawsub/` | همیشه متن خام ساب (برای fetch صفحه‌ی زیبا) |
| `/view/` | صفحه‌ی زیبای ساب برای وارد کردن دستی لینک |
| `/` و بقیه | پروکسی به اینباند روی `8080` |

> اگر هنوز اینباندی روی پورت `8080` نساخته باشید، باز کردن `/` یا `/dashboard/` خطای `Connection refused` در لاگ nginx می‌دهد. این طبیعی است.

## متغیرهای محیطی

در Railway، بخش **Variables** این دو متغیر را بسازید:

| متغیر | توضیح |
|---|---|
| `PANEL_USER` | نام کاربری ورود به پنل |
| `PANEL_PASS` | رمز عبور پنل (قوی انتخاب کنید) |

اگر هر کدام تعریف نشده باشد، `start.sh` با پیام `PANEL_USER is not set` یا `PANEL_PASS is not set` متوقف می‌شود.

## دیپلوی روی Railway

1. ریپوی گیت‌هاب را به یک پروژه‌ی جدید در Railway وصل کنید (Deploy from GitHub repo).
2. Railway به‌طور خودکار `Dockerfile` را تشخیص می‌دهد و بیلد می‌کند.
3. در بخش **Variables**، `PANEL_USER` و `PANEL_PASS` را اضافه کنید.
4. در بخش **Settings → Networking** یک دامنه‌ی عمومی (Generate Domain) بسازید و در صورت نیاز پورت مقصد را `3000` بگذارید.
5. بعد از دیپلوی موفق، پنل روی این آدرس باز می‌شود:

```
https://<your-app>.up.railway.app/managepanel/
```

### لاگ‌هایی که باید ببینید

```
🚀 Starting X-UI + nginx reverse proxy...
🔧 Applying panel settings via x-ui CLI...
✅ iptables OK        (یا ❌ iptables NOT permitted)
▶️ Starting x-ui in background...
▶️ Starting nginx in foreground on port 3000...
```

خروجی `x-ui setting -show true` باید پورت `2053` و مسیر `/managepanel/` را نشان دهد.

## راه‌اندازی اولیه بعد از دیپلوی

1. وارد `/managepanel/` شوید و با `PANEL_USER` / `PANEL_PASS` لاگین کنید.
2. **Settings → Panel → Time zone**: مقدار `Asia/Tehran` را بگذارید، ذخیره کنید و پنل را ریستارت کنید. (ساعت خود کانتینر از قبل در Dockerfile روی تهران تنظیم شده است.)
3. **Settings → Subscription**: ساب را فعال کنید و این مقادیر را بگذارید:
   - پورت: `2096`
   - مسیر (URI Path): `/sub/`
4. یک **Inbound** بسازید (مثلاً VLESS + WebSocket) با پورت **`8080`**.
5. کلاینت بسازید و لینک اشتراک آن را بردارید.

## سیستم لینک اشتراک (Sub)

لینک اشتراک روی `/sub/<subId>` قرار دارد و nginx بر اساس `User-Agent` تصمیم می‌گیرد:

- **اپ‌های VPN** (v2ray، NekoBox، Hiddify، Streisand، Clash، sing-box، Shadowrocket، Karing و ...) مستقیم به سرویس ساب (`2096`) وصل می‌شوند و متن خام می‌گیرند.
- **مرورگر** صفحه‌ی `sub-view.html` را می‌بیند. این صفحه با fetch از `/rawsub/` داده را می‌گیرد و کارت، QR و دکمه‌ی کپی نشان می‌دهد.

برای تست سلامت بک‌اند ساب، در مرورگر این را باز کنید:

```
https://<your-app>.up.railway.app/rawsub/<subId>
```

اگر متن base64 نشان داد، بک‌اند ساب سالم است.

> یک `User-Agent` خالی هم به‌عنوان اپ کلاینت شناخته می‌شود تا ابزارهایی که UA نمی‌فرستند هم متن خام بگیرند.

## محدودیت IP و Fail2ban

ویژگی «محدودیت IP» در 3x-ui به Fail2ban و دسترسی `iptables` نیاز دارد. روی Railway این موارد مهم است:

1. **دسترسی iptables:** `start.sh` موقع اجرا تست می‌کند و در لاگ `✅ iptables OK` یا `❌ iptables NOT permitted` چاپ می‌کند. اگر `❌` بود، بن واقعی IP ممکن نیست.
2. **IP واقعی کاربر:** nginx الان `X-Real-IP` را برابر `$remote_addr` (آی‌پی پروکسی Railway) می‌گذارد. برای اینکه x-ui آی‌پی واقعی کاربر را ببیند، باید هدر `X-Forwarded-For` در تنظیمات اینباند (sockopt) برای Xray قابل اعتماد تعریف شود. نام دقیق گزینه به نسخه‌ی Xray بستگی دارد.
3. اگر هنوز پیام «Fail2ban نصب نشده است» می‌بینید، یعنی جیل Fail2ban مخصوص x-ui هنوز تنظیم نشده است.

تا زمانی که این موارد حل نشده، فیلد «محدودیت IP» را روی `0` (نامحدود) بگذارید و برای کنترل مصرف از **حجم ترافیک** و **انقضا** استفاده کنید.

## آپدیت نسخه‌ی 3x-ui

`Dockerfile` به‌صورت پیش‌فرض آخرین نسخه‌ی پایدار را می‌گیرد:

```dockerfile
RUN curl -fL https://github.com/MHSanaei/3x-ui/releases/latest/download/x-ui-linux-amd64.tar.gz -o /tmp/x-ui.tar.gz
```

- برای آپدیت، کافی است Railway را **Redeploy** کنید (بدون کش بیلد).
- برای ثابت نگه داشتن نسخه، `latest/download` را با `download/vX.Y.Z` جایگزین کنید، مثلاً:

```dockerfile
RUN curl -fL https://github.com/MHSanaei/3x-ui/releases/download/v3.11.0/x-ui-linux-amd64.tar.gz -o /tmp/x-ui.tar.gz
```

- پرچم `-f` باعث می‌شود اگر فایل پیدا نشد، بیلد همان‌جا خطا بدهد.
- دیتابیس پنل داخل کانتینر است. برای اینکه بعد از هر دیپلوی پاک نشود، یک **Volume** در Railway روی مسیر `/etc/x-ui` وصل کنید.

## اسکریپت برندسازی nginx

در `nginx.conf.template` داخل `location /managepanel/` یک بخش `sub_filter` وجود دارد که:

- متن‌های `Heimdall` را در پاسخ‌های JS/JSON با `Hadi panel` عوض می‌کند.
- با یک اسکریپت کوچک که قبل از `</body>` تزریق می‌شود، لینک‌ها و شماره‌ی نسخه‌ی نمایش‌داده‌شده را تغییر می‌دهد.

این بخش برای پنل قدیمی Heimdall نوشته شده بود. با 3x-ui نسخه‌ی ۳ به بعد (فرانت‌اند Vue 3) احتمالاً اثری ندارد و عدد نسخه‌ی ثابت `3.4.2` داخل آن ممکن است با نسخه‌ی واقعی فرق کند. در صورت نیاز می‌توانید آن را به‌روز یا حذف کنید.

## نکات امنیتی

- **هیچ‌وقت** یوزرنیم و رمز را داخل `start.sh` یا هر فایل دیگری در ریپو ننویسید؛ فقط از متغیرهای محیطی استفاده کنید.
- اگر ریپو **Public** است، هر رمزی که قبلاً در آن نوشته شده باید تغییر داده شود (حتی بعد از حذف از فایل، در تاریخچه‌ی گیت باقی می‌ماند).
- مسیر `/managepanel/` را حدسی‌تر از `/` نکنید و رمز قوی انتخاب کنید.
- اگر ریپو را Public نگه می‌دارید، مطمئن شوید هیچ توکن یا کلیدی در فایل‌ها نیست.

## عیب‌یابی

| مشکل | علت محتمل | راه‌حل |
|---|---|---|
| لاگ پر از `connect() failed (111)` به `127.0.0.1:8080` | هنوز اینباندی روی پورت `8080` ساخته نشده | یک اینباند روی `8080` بسازید؛ این خطا برای `/`، `/dashboard/` و favicon طبیعی است |
| `/managepanel/` باز نمی‌شود یا ۴۰۴ می‌دهد | مسیر پنل تنظیم نشده یا نسخه‌ی x-ui قدیمی است | خروجی `x-ui setting -show true` را در لاگ چک کنید؛ نسخه‌ی x-ui را به آخرین ریلیز ببرید |
| کانتینر با `PANEL_USER is not set` می‌ایستد | متغیرها تعریف نشده‌اند | در Railway متغیرها را اضافه کنید |
| لینک ساب در مرورگر `Unexpected Application Error! 404 Not Found` می‌دهد | مسیر یا تنظیمات ساب با `/sub/` نمی‌خواند | `/rawsub/<subId>` را تست کنید؛ در پنل مسیر ساب را `/sub/` و پورت را `2096` بگذارید |
| «رکورد آی‌پی وجود ندارد» یا «Fail2ban نصب نشده» | Fail2ban/iptables یا IP واقعی کاربر در دسترس نیست | بخش [محدودیت IP و Fail2ban](#محدودیت-ip-و-fail2ban) را ببینید |
| بیلد با خطای دانلود تمام می‌شود | نام فایل ریلیز یا آدرس عوض شده | لیست Assets ریلیز در گیت‌هاب 3x-ui را چک کنید |
| تنظیمات پنل بعد از دیپلوی مجدد پریده | دیتابیس روی Volume نیست | یک Volume روی `/etc/x-ui` وصل کنید |
